# AGENTS.md

Guidance for agents and people who add or change skins here. The README says what the repository is; this file says
how to work in it without breaking a skin.

## Sent here to install skins?

If a person gave you this repository so you install skins into their OMNE (资产 → 皮肤) by what they like, one or a
batch: follow `skills/skin-gallery/SKILL.md`. It finds themes by their wishes (`npm run dream -- --find`), shows their
pictures (`--sheet`), converts a batch (`npm run dream -- ver_a ver_b …`) and publishes each with `OmneExtensions`.
You change nothing in the repository for that; what it converts goes to `local-skins/` (ignored by git).

## Layout rules

- One skin per `skins/<name>/`. `<name>` is lower-case letters, digits and hyphens, and equals `name` in
  `package/plugin.json`.
- `package/` is exactly what gets published. Put nothing in it but `.js`, `.css`, `.json` and images
  (`.png .jpg .webp .avif .svg`). Docs, licences, source art and tools live beside it, never inside.
- Every skin has `README.md`, `LICENSE` (the scoped MIT of the root), `NOTICE.md` and `package/credits.json`. Third-party art also carries its licence text
  (for example `LICENSE-ARTWORK`).
- Start a skin with `npm run new -- <name> "<summary>"`.

## The host's rules (all enforced by `npm run validate`)

- A skin installs all or nothing: one refused member and the whole skin falls back to the built-in look.
- Tokens: only names the interface sets at `:root` under `--omne-` (see `contract/omne-contract.json`). The
  `--kami-*` palette underneath is not a token. Tokens put on a part other than `shell.app` apply to that part's
  subtree, so set the `--omne-*` names there, not the palette they alias.
- Values: characters `A-Za-z0-9 #%.,()+*/_-` only (no quotes, colons or semicolons, so a font family with spaces
  cannot be quoted); calls only `var calc min max clamp rgb rgba hsl hsla hwb lab lch oklab oklch color color-mix
  light-dark`. No `url()` (use `file(path)`), no gradients, no `blur()`.
- Sizes move with the size step: scale lengths with `calc(var(--omne-size) * 12px)` rather than fixed `12px`.
- Colours: write `light-dark(light, dark)`.
- Style states: `base hover focus-visible active selected open disabled`. `selected` matches
  `[data-selected="true"]`, `[aria-current="page"]` and the like.
- A drawing module imports nothing; it uses `{ React, ui, shell, files }` as handed in. `files.url('art/x.webp')`
  gives an image's address.
- `shell.part-render` drawings get `{ props, part, builtIn }` and must spread `part` on their outermost element.
  `shell.icon` / `shell.piece` drawings get `{ subject, generic }`.
- No hooks in the drawing itself: put state in a component of its own and return `React.createElement(Component)`.
- The desktop page's CSP is `style-src 'self'`: a `<style>` element in a drawing is blocked. Use inline style
  objects (React sets them through CSSOM, which CSP allows), and the Web Animations API for motion.
- Light or dark at run time: `document.documentElement.dataset.theme` is `light` or `dark`.
- Wrapping a part's `builtIn()` that already carries the part attribute (for example `session.composer`) puts the
  attribute on two elements, and part styles then apply twice. Prefer `shell.part-style` for such parts.

## Checks

- `npm run check` must pass before a skin is published or committed. It runs `validate` and `node --test 'tests/**/*.test.mjs'`.
- When the OMNE app changes, run `npm run sync-contract -- --source <omne-harness-lite checkout>` and commit the new
  snapshot together with any skin fixes. When a host rule changes, update `scripts/lib/rules.mjs` (each block names
  the file it mirrors) and its tests.
- validate is a smoke test, not a screenshot. After publishing, wear the skin and look at it in light and dark,
  and check `OmneExtensions show` reports every member in effect.

## Artwork is fetched, not committed

- `skins/*/package/art/` is ignored by git. `npm run art` (`scripts/fetch-art.mjs`) checks out each skin's pinned
  upstream into `.cache/upstream/` and derives the art; the result must be byte-identical to what was published.
  A skin with new art adds its upstream and its build to `UPSTREAMS` there.

## Generated skins (`dream-*`)

- `skins/dream-*` are generated by `npm run dream -- --upstream <Codex-Dream-Skin checkout>` from
  `sources/codex-dream-skin.json`, `scripts/lib/dream-palette.mjs` and `templates/dream/draw/dream.js`. Do not edit
  their files by hand: change the mapping or the template, regenerate, and commit the regenerated skins with it.
- A generated skin covers every place `deepseek-skin` (the most complete skin) changes; `tests/dream-palette.test.mjs`
  holds it to that. A place added to `deepseek-skin` needs its counterpart in `membersOf` (its art, if any, in
  `scripts/lib/dream_art.py`). When the mapping or the drawings change, raise `REVISION` in
  `scripts/import-dream-skin.mjs`, so skins converted before are converted again.
- `sources/dreamskin-community.json` is generated by `npm run dream -- --sync-catalogue`; do not edit it. It holds
  metadata only. The licences it takes are decided in `scripts/lib/licences.mjs` (with tests).
- A Dream theme enters `skins/` only through an entry in `sources/codex-dream-skin.json` that pins its files by
  sha256 and states why its art may be redistributed. Community themes (api.dreamskin.cc) and themes without such
  rights are converted into `local-skins/` (ignored by git) and never committed.

## Art

- Ship only art you may ship. Prefer art drawn for this repository. For community art, keep the full attribution
  chain in `NOTICE.md` and `credits.json`, and respect its licence (for example CC BY-NC-SA: non-commercial,
  share-alike).
- Keep images small: WebP, about twice the displayed size. Generate derived art with a script under `tools/` so it
  can be rebuilt from a pinned upstream commit.
